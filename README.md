# Game of Games

A comedic text-adventure with walk-around exploration. Deployed to GitHub Pages.

Live: https://jmartucc97.github.io/GameOfGames/story_v2.html

## How this project is organized

The deployed game is a single file (`story_v2.html`) generated by a build script
that concatenates the source files in `src/`.

```
GameOfGames/
  story_v2.html          ← deployed file (generated, do not edit by hand)
  audio/                 ← mp3 tracks for music routing
  build.js               ← Node script that builds story_v2.html from src/
  package.json
  src/
    index.html           ← HTML shell (head, body, script tag placeholders)
    styles.css           ← all CSS
    engine/              ← engine code (state, render, explore, music, sfx)
      util.js
      state.js
      sfx.js
      music.js
      explore.js
      render.js
    data/                ← game content
      sprites.js         ← all sprite data URLs (SPRITES object)
      items.js           ← pile items + pileChoices helper
      rooms.js           ← EXPLORE_ROOMS config
      scenes/            ← scenes split by narrative module
        intro.js
        driveway.js
        john_basement.js
        storage.js
        plumpy.js
        backroom.js
        samara.js
        john_first.js
        cat.js
        fracking.js
        pit_gauntlet.js
        epa.js
```

## Daily workflow

```powershell
# 1. Edit source files in src/
#    (e.g. open src/data/scenes/driveway.js to tweak the trader)

# 2. Build
node build.js

# 3. Commit both the source AND the rebuilt HTML
git add story_v2.html src/
git commit -m "..."
git push
```

**Don't skip step 2.** If you push without rebuilding, GitHub Pages serves the
old `story_v2.html` even though `src/` is updated. The page on phones won't
reflect your changes.

## How the build works

`build.js` concatenates everything in a specific order so that data is defined
before the engine uses it:

1. **CSS** → inlined into `<style>` in the page head
2. **Data files** in order: sprites → items → rooms → scenes
3. **Engine files** last (they reference the data globals)

The output is a single self-contained `story_v2.html` at the repo root.

## Scene-file convention

Each scene file looks like:

```javascript
Object.assign(SCENES, {
  scene_xyz: {
    sprite: "some_sprite",
    text: "Some text.",
    choices: [
      { text: "Continue", next: "other_scene" }
    ]
  },
  // ...
});
```

`SCENES` is declared as an empty `const SCENES = {};` in the engine, and each
scene file adds to it via `Object.assign`. This means the order of scene files
doesn't matter, and adding a new scene file means: create it and add it to
`build.js`'s file list.

## Skill / sprite convention

All sprites live in `src/data/sprites.js` as `Object.assign(SPRITES, {...})`.
Add new sprites by editing that file. Sprites are base64 data URLs so they
travel inline with the HTML — no separate asset files to deploy.

## Reverting to the pre-restructure state

If anything breaks beyond repair, the entire previous codebase is preserved on
the `pre-restructure` branch:

```powershell
git reset --hard pre-restructure
git push --force
```

(Force-push only if you're sure. This rewrites history.)
